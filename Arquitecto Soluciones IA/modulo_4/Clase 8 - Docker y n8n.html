Subsistema Docker

Entorno bajo control.

Docker ejecuta aplicaciones dentro de contenedores aislados y reproducibles. La imagen define el entorno; el contenedor es una instancia viva de esa definición. No es una computadora completa: comparte el núcleo del sistema anfitrión.

Subsistema n8n

Órbitas de datos.

En n8n construimos workflows. Un trigger inicia el recorrido; cada nodo recibe, transforma o envía información; las conexiones determinan el camino.

⚡ Trigger

Inicia el flujo.

Cada conexión es un contrato.

Los datos viajan como items JSON. La salida de un nodo promete campos y tipos; el siguiente espera recibirlos. Cambiar un nombre o un tipo puede romper ese contrato.

Sistema integrado

Compose define la misión.

Docker Desktop es el motor. Compose es la receta que declara imagen, puerto y volumen. n8n es la aplicación donde diseñamos workflows.

DESKTOP → MOTORCOMPOSE → RECETAn8n → APLICACIÓN
services:
  n8n:
    image: n8nio/n8n
    ports:
      - "5678:5678"
    volumes:
      - n8n_data:/home/node/.n8n
Lectura final

Docker prepara.
n8n orquesta.
JSON conecta.

Podemos reemplazar el contenedor sin perder el trabajo porque los datos viven en el volumen. Podemos comprender el workflow siguiendo el contrato JSON que atraviesa sus nodos.
